# WO-ASIMOV-001: Asimov 1 observation connector

## Summary
Deliver a free, open-source Menlo SDK connector for Asimov 1 with useful local inspection without a paid license. Observe physical telemetry, opt-in application command attempts and official SDK recordings without introducing robot control. Emit the existing robotics journal contract so the merged Physical AI ingestion and encrypted cloud transport can consume the same evidence. Hardware qualification remains a separate acceptance gate and must never be inferred from fixtures or simulation.

Reuse `clawmetry/robotics.py` for the OSS CLI seam, `clawmetry/local_store.py` and daemon query plumbing for DuckDB ownership, `clawmetry/sync.py` for encrypted snapshots, and `clawmetry/extensions.py` for existing plugin seams. Follow the bounded journal schema and immutable replay behavior in merged Pro #338 (`clawmetry_pro/robotics/recorder.py`, `store.py`) without importing private Pro in the free collector. Pro/cloud implementations remain separately owned. Pending RP1 #340 owns humanoid.js, shared renderer, hardware catalogue and its deployment; this change shall not edit those worktrees or claim that viewer already supports physical Asimov.

Create the feature package `clawmetry/asimov/` with CLI, normalization/recording import, SDK instrumentation, observer connection and bounded journal modules as implementation warrants. Add an Asimov-specific store module, `routes/asimov.py`, `/asimov` local view, and dedicated native static assets to make free local use real. Wire the provider to the existing daemon-ready hook and authenticated local query allowlist. Emit `payload.asimov` in the shared encrypted system snapshot and implement the matching cloud rendering path; use daemon-owned DuckDB reads and existing static/template conventions. Add focused tests under `tests/test_asimov_*.py`, technical documentation `docs/ASIMOV.md`, and an executable public example if it materially helps installation. Keep optional Menlo/LiveKit dependencies outside core import/startup paths. Menlo requires Python 3.12 but importing ClawMetry must preserve its declared Python floor.

## Components And Flow
`AsimovObserver` accepts an explicit user-supplied Observe credential and receives telemetry only. It uses the documented Menlo LiveKit surface and requests data-only subscription where the actual SDK permits; never silently start media subscriptions or upgrade credential authority. `AsimovSdkTracer` is explicitly installed by an application and records command requests, returns and exceptions while preserving original call behavior; a return value is not command acceptance or movement success. `AsimovRecordingImporter` reads official SDK recording metadata/state/command records with bounded memory, retained source timestamps and source identity.

All three sources pass through `AsimovNormalizer` into `AsimovJournalWriter`. The writer produces `clawmetry.robotics.v1` events with UUID32 run identity, positive monotonic sequence, nanoseconds represented as decimal strings, environment, dropped totals and bounded JSON data. Capture source clock separately from host receipt clock; retain null/missing measurements and unknown outcomes. Emit `run.started`, `observation`, explicit command-evidence events, connection/gap/fault transitions and `run.ended` as supported by actual evidence. `observation` is required for compatibility with merged #338 latest-feedback snapshots; raw structured `joints`/`base` evidence remains available for future generic humanoid rendering.

`AsimovLocalStore` ingestion operates on the daemon writer connection, never in a request handler or robot control callback. Deduplicate immutable event identities and commit cursor advancement with evidence. `AsimovReadView` reads persisted summaries/events through the daemon proxy and presents robot mode, freshness, available 25-joint current/temperature/position/velocity, orientation, battery, alerts and command evidence. Free local operations shall work with Pro absent and licensing enforced. Existing Pro ingestion/snapshot reuse shall be verified by contract test; any free backend bridge shall preserve the existing plugin's behavior rather than shadowing its hook globally.

6. Run focused tests and real available SDK recording/observer behavior. Explicitly separate hardware-free acceptance from a real Asimov test. Review independently, resolve findings, then follow repository PR, CI, release, cloud promotion and served-artifact verification gates.
