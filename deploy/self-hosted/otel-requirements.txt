# Hash-pinned install set for the OTLP extra baked into the SIGNED self-hosted
# release image (Dockerfile.release in this directory).
#
# Direct requirements: opentelemetry-proto>=1.20.0 protobuf>=4.21.0
#
# Those ranges are what this file replaces. Dockerfile.release installs the
# published wheel as `pip install "$1[otel]"`, and the `[otel]` extra resolved
# both names live at build time against floors that have spanned four major
# protobuf versions. The base image on the FROM line is pinned by digest so an
# identical build pulls identical bytes; a live resolve on the very next layer
# gave that back.
#
# This matters more here than it does for the root Dockerfile, which got the
# same treatment first. This image is PUBLISHED and SIGNED: container-image.yml
# pushes it to ghcr.io/vivekchand/clawmetry, cosign signs the index and every
# platform manifest, and an SPDX SBOM is attested to each platform digest. An
# SBOM and a signature attest to bytes. If two builds of the same clawmetry
# version can bake different protobuf bytes, the signature still verifies and
# the SBOM still validates -- they just describe whatever the builder happened
# to resolve that morning. Pinning is what makes the attestation mean "this
# version", rather than "this build".
#
# Deliberately a SECOND file rather than reusing
# .github/requirements/docker-otel.txt, which pins the same two names today.
# Two reasons, and the first is not a preference:
#
#   1. It is not reachable. container-image.yml builds with
#      `context: deploy/self-hosted` (tests/test_selfhosted_image_publish.py
#      pins that), so nothing under .github/ is in the build context. A narrow
#      context is the point -- it is what stops repo source reaching an image
#      that must carry only the published wheel.
#   2. They move for different reasons. That file describes the from-source
#      development image; this one describes the artifact orgs run in
#      production. A dev-motivated edit there must not silently change what
#      ships signed. Same names today, separate reasons to change, so separate
#      files -- the same argument that file's own header makes for staying
#      separate from ci-otel-extra.txt.
#
# Not folded into the wheel's own requirements either: these are the optional
# `otel` extra (setup.py), baked in on purpose because the daemon-free intake
# path (a runtime exporting OTLP straight at this server) answers 501 to
# http/protobuf without them. A receiver that must be told to
# `pip install clawmetry[otel]` before it accepts data is not a receiver.
#
# Installed with `pip install --require-hashes`, which refuses to install
# anything not listed here with a matching hash -- so the image gets the exact
# artifacts this file names, or the build fails. Every transitive dependency is
# present because --require-hashes demands the whole closure; here the closure
# is just these two names (opentelemetry-proto requires protobuf, protobuf
# requires nothing), which is why the file is this short.
#
# Each version lists the sha256 of EVERY distribution PyPI publishes for it
# (wheels for each platform, plus the sdist). pip accepts a download matching
# any one of them, so the pin does not quietly depend on the builder resolving
# to the same wheel this file was generated against. That is load-bearing here:
# this image is built for linux/amd64 AND linux/arm64 in the same job.
#
# On the interpreter: the base image is python:3.14-slim. protobuf 7.36.1 ships
# a cp310-abi3 manylinux wheel, ABI-compatible with 3.14, and
# opentelemetry-proto 1.44.0 is a pure-python py3-none-any wheel. Both declare
# requires_python >=3.10. A protobuf release that drops the abi3 wheel would
# need this checked again before the bump lands.
#
# Updating: the `pip` entry for /deploy/self-hosted in .github/dependabot.yml
# advances this file and rewrites the --hash lines along with the version, so a
# bump arrives already verifiable. Without that entry the pin would simply
# freeze the signed image at today's CVEs, which is the other end of the same
# problem the unpinned range was at.
