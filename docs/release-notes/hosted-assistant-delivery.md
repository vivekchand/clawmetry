# Hosted Assistant delivery and interrupted-reply recovery

Hosted Assistant requests now reach the node independently of long collection and snapshot passes. One wake worker delivers encrypted requests to the existing executor and forwards general wake hints to the collection loop. Existing request expiry, leases, cancellation, read-only safeguards and final persistence remain enforced.

The transport can interrupt stalled proxy CONNECT, TLS handshakes and response reads while retaining the daemon's operating-system trust store, configured certificate authorities and hostname validation. Exact Unicode node identifiers remain supported through URL and encrypted exchange bindings.

Queries that group model names after trimming spaces now run successfully. The correction preserves the existing restrictions on qualified calls and unsafe functions.

After an interrupted reply or Stop, Assistant offers a read-only history refresh and can reopen a known saved conversation. A key error during chat offers the existing unlock action without automatically resending the question.

Local verification: the required Assistant suite passed 408 tests (two Windows-only tests run in the native CI matrix), and 67 frontend tests passed. Coverage includes encrypted request and receipt recovery, a collector held beyond the 30-second start validity, real socket/proxy cancellation, certificate and hostname validation, and explicit recovery without resubmitting paid work. Actual hosted verification observed text arriving before completion, a chart with four successful sources, Save-to-Home, six panels restored after a fresh reload, and conversation history restoring the chart and follow-up table. Stop terminated the active CLI child in under 0.6 seconds, and a read-only persistence check confirmed the canceled question was not stored. Native Windows, macOS and Linux TLS checks passed. A settled 90-second off-tab observation found no Assistant browser requests; the node made six bounded held wake polls. Feature #6340 passed all functional CI and the required gate rerun before its normal merge. The existing gate applied its documented 1,200-second policy to an undecided Drift status.
